# UAES-02-005 — PRODUCT FLOW & STATE MACHINE STANDARD

**Version:** 1.0.0  
**Status:** DRAFT

## 1. 目的

规范产品流程、业务状态、状态转换和异常处理，防止 AI 只实现页面操作而忽略业务状态一致性。

## 2. 适用范围

以下业务必须优先建立状态机：

- 用户账户。
- 登录会话。
- 充值订单。
- 支付订单。
- 退款订单。
- 套餐订阅。
- AI 请求。
- 异步任务。
- 消息通知。
- 审核流程。

## 3. 状态机定义

每个状态机必须定义：

- State Machine ID。
- 业务对象。
- 状态集合。
- 初始状态。
- 终止状态。
- 合法转换。
- 触发事件。
- 前置条件。
- 执行行为。
- 失败处理。
- 超时策略。
- 幂等要求。
- 并发策略。

## 4. 状态转换规则

状态转换必须采用显式定义。

```yaml
state_machine:
  id: SM-0001
  name: Example Workflow
  initial_state: PENDING

  states:
    - PENDING
    - PROCESSING
    - SUCCEEDED
    - FAILED

  transitions:
    - from: PENDING
      event: START
      to: PROCESSING

    - from: PROCESSING
      event: SUCCESS
      to: SUCCEEDED

    - from: PROCESSING
      event: FAILURE
      to: FAILED

  terminal_states:
    - SUCCEEDED
    - FAILED
```

以上只是状态机结构示例，不是 Uter 真实支付或任务状态定义。

## 5. 状态转换约束

1. 未定义的转换必须拒绝。
2. 终止状态不得被普通事件随意改变。
3. 重复事件必须具备明确处理方式。
4. 并发事件必须定义一致性策略。
5. 超时必须具有明确处理规则。
6. 失败必须能够追踪原因。
7. 状态变化必须保留必要审计信息。
8. 重要状态转换必须具备测试。

## 6. 异步业务

异步任务必须考虑：

- 重试。
- 幂等。
- 超时。
- 死信处理。
- 重复消息。
- 消息乱序。
- 并发竞争。
- 补偿操作。
- 最终一致性。

## 7. 资金业务特别要求

支付、充值、退款和余额变动必须：

- 明确订单状态。
- 明确支付渠道状态与内部订单状态的映射。
- 明确回调验签。
- 明确金额校验。
- 明确幂等键。
- 明确重复通知处理。
- 明确主动查询和对账机制。
- 明确到账条件。
- 明确异常恢复流程。

不能仅凭客户端支付成功页面确认资金到账。

## 8. 状态机测试

每个重要状态机至少测试：

- 每个合法转换。
- 非法转换。
- 重复事件。
- 并发事件。
- 超时。
- 失败恢复。
- 终止状态保护。

## 9. 强制规则

| Rule ID | 规则 | 级别 |
|---|---|---|
| UAES-02-005-001 | 关键业务必须定义状态集合 | MUST |
| UAES-02-005-002 | 合法状态转换必须明确 | MUST |
| UAES-02-005-003 | 非法转换必须拒绝 | MUST |
| UAES-02-005-004 | 异步操作必须定义重试和幂等 | MUST |
| UAES-02-005-005 | 重要状态转换必须测试 | MUST |
