# UAES-04-008 — Database & Data Modeling Standard

**Standard ID:** UAES-04-008  
**Version:** 1.0.0  
**Status:** DRAFT  
**Technology baseline:** GORM / SQLite / MySQL / PostgreSQL

## 1. Purpose

建立数据库结构、数据所有权、数据完整性、迁移、索引、事务和多数据库兼容性标准。

## 2. Data modeling principles

- UAES-DB-001：数据模型必须反映明确的业务含义。
- UAES-DB-002：每个核心实体必须有稳定主键。
- UAES-DB-003：字段必须明确类型、单位、可空性和默认值。
- UAES-DB-004：时间字段必须明确时间语义。
- UAES-DB-005：金额必须明确币种和精度。
- UAES-DB-006：状态字段必须有合法状态集合。
- UAES-DB-007：关键业务关系必须有明确约束。
- UAES-DB-008：不得仅依赖前端校验保证数据完整性。

## 3. Data ownership

每个核心业务实体必须有唯一写入所有者。

其他模块如需修改实体，必须通过所有者提供的业务接口完成。

资金、支付和 Token 计费数据必须具备审计追踪能力。

## 4. Database portability

Uter 已知数据库方向包括 SQLite、MySQL 和 PostgreSQL。

- UAES-DB-009：必须明确各数据库的实际支持级别。
- UAES-DB-010：不得假设不同数据库对事务、锁、索引和类型的行为完全一致。
- UAES-DB-011：数据库专有能力必须有兼容性说明。
- UAES-DB-012：核心迁移必须在实际支持的数据库上验证。
- UAES-DB-013：不得以 SQLite 测试结果代替 MySQL 或 PostgreSQL 的生产行为验证。

如果某数据库仅用于开发或测试，必须明确标注，不得宣称全场景兼容。

## 5. Migration

每次结构变更必须有迁移记录。

- UAES-DB-014：禁止未经记录的生产结构变更。
- UAES-DB-015：迁移必须可重复识别执行状态。
- UAES-DB-016：迁移必须有前置条件和后置条件。
- UAES-DB-017：破坏性迁移必须有数据备份和恢复方案。
- UAES-DB-018：大表迁移必须评估锁表和性能影响。
- UAES-DB-019：应用版本必须与数据库结构兼容。
- UAES-DB-020：迁移失败必须能够明确定位和处理。

优先采用 Expand-and-Contract：

1. 扩展旧结构；
2. 部署兼容代码；
3. 回填或迁移数据；
4. 验证新旧路径；
5. 停止使用旧字段；
6. 在安全窗口删除旧结构。

不得在一个未经验证的步骤中同时删除旧字段并部署依赖新字段的代码。

## 6. Transactions

- UAES-DB-021：业务事务边界必须明确。
- UAES-DB-022：多表强一致性写入必须在适当事务内完成。
- UAES-DB-023：事务必须尽可能短。
- UAES-DB-024：不得在持有数据库事务和锁期间执行无必要的外部网络请求。
- UAES-DB-025：事务失败必须明确回滚。
- UAES-DB-026：重试必须考虑事务是否可能已经提交。
- UAES-DB-027：跨服务操作不得假设本地数据库事务能覆盖外部系统。

## 7. Indexes and query performance

- UAES-DB-028：高频查询必须评估索引。
- UAES-DB-029：复合索引必须考虑实际查询条件和顺序。
- UAES-DB-030：避免不必要的全表扫描。
- UAES-DB-031：列表查询必须有合理限制。
- UAES-DB-032：索引新增和删除必须考虑写入成本。
- UAES-DB-033：关键查询应有执行计划或性能证据。

## 8. Financial and usage data

支付、充值、退款、余额和 Token 使用相关数据必须特别满足：

- 业务单据与资金变动记录分离；
- 余额变化有可审计来源；
- 重复通知不会重复入账；
- 账务流水不得通过覆盖原记录掩盖历史变化；
- 金额、币种和精度明确；
- 订单状态与渠道状态有映射；
- 失败、超时、补偿和对账有明确处理方式；
- 关键操作具备唯一约束和并发控制。

不得仅依赖修改一个用户余额字段来替代完整的资金变更记录。

## 9. Data deletion and retention

- UAES-DB-034：删除策略必须区分物理删除、逻辑删除和归档。
- UAES-DB-035：涉及审计、资金和计费的数据必须评估保留要求。
- UAES-DB-036：级联删除必须经过业务影响分析。
- UAES-DB-037：数据导出和删除必须遵守权限与隐私要求。

## 10. Acceptance criteria

- 核心数据模型有明确说明；
- 数据所有权明确；
- 迁移可追踪；
- 多数据库行为得到验证；
- 事务边界合理；
- 关键查询有性能依据；
- 资金和计费数据具备审计能力；
- 迁移失败和回滚路径明确。
