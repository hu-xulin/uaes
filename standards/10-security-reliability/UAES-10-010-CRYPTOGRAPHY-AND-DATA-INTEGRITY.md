# UAES-10-010 — Cryptography and Data Integrity

| Field | Value |
| --- | --- |
| ID | UAES-10-010 |
| Version | 1.0.0 |
| Status | DRAFT |

## 1. Cryptographic Policy

- 只使用当前受支持、经过公开审查的密码学算法和库。
- 禁止自行设计加密算法、签名协议或随机数生成器。
- 随机数必须使用密码学安全随机源。
- 密码哈希必须使用专用 Password Hashing 算法和适当参数。
- 密码学参数必须可配置、可审计并有升级策略。

## 2. Key Management

密钥必须具备生成、存储、使用、轮换、撤销、销毁和审计生命周期。密钥用途必须隔离，不得将同一密钥无差别用于签名、加密和认证。

## 3. Integrity

重要数据和产物必须根据风险采用签名、MAC、哈希、版本检查或其他完整性机制。

哈希用于完整性校验不自动等同于身份认证；需要认证时必须使用带密钥或数字签名机制。

## 4. Payment Signature

支付签名验证 MUST 遵循对应渠道官方协议：

- 使用正确的验签公钥/证书；
- 校验签名算法和签名内容；
- 校验商户身份；
- 校验订单号、金额、币种和交易状态；
- 校验通知来源及重放条件；
- 记录验证结果。

不得硬编码未经轮换设计的证书或私钥。

## 5. Acceptance

加密、签名、密钥轮换和完整性校验均有测试；不存在自制密码算法或不受控密钥复用。
