# UAES-02-GATE-001 — Product Engineering Quality Gate

| Field | Value |
|---|---|
| Gate ID | UAES-02-GATE-001 |
| Domain | UAES-02 Product Engineering |
| Version | 1.0.0 |
| Status | DRAFT |
| Gate Nature | Blocking Gate |

## 1. 目的

确保进入工程实施的产品需求具备明确目标、范围、业务规则、验收标准、影响分析和授权依据；确保实现结果可追踪回原始需求。

## 2. 检查项

| ID | 检查项 | 通过条件 |
|---|---|---|
| P02-G01 | 需求身份 | 每项需求具有唯一且稳定的 ID |
| P02-G02 | 需求来源 | 来源、提出者、创建时间和证据可追踪 |
| P02-G03 | 目标与范围 | 目标、非目标、范围边界明确 |
| P02-G04 | 用户价值 | 用户角色、问题、预期价值明确 |
| P02-G05 | 业务规则 | 关键规则有唯一 ID、来源、状态和责任人 |
| P02-G06 | 验收标准 | 验收条件可观察、可执行、可判定 |
| P02-G07 | 流程与状态 | 主流程、异常流程、状态转换和终止条件明确 |
| P02-G08 | 非功能需求 | 性能、安全、可靠性、可访问性等要求已评估 |
| P02-G09 | 变更影响 | 业务、架构、数据、接口、设计、安全、测试、平台和交付影响已评估 |
| P02-G10 | 风险与依赖 | 风险等级、依赖、阻塞条件和未决问题已记录 |
| P02-G11 | 追踪关系 | 需求能够关联设计、实现、测试和验收证据 |
| P02-G12 | 授权边界 | 需求批准与 AI 工程执行授权分离 |
| P02-G13 | 资金业务 | 涉及支付、退款、充值、余额时，资金状态和对账规则完整 |
| P02-G14 | 文档一致性 | 需求、业务规则、流程和验收文档之间不存在未处理冲突 |

## 3. 阻断规则

以下情况必须 BLOCK：

1. 需求缺少唯一 ID 或来源。
2. 关键业务规则仍存在未经确认的假设。
3. 验收标准无法客观判定。
4. 关键状态转换或异常路径缺失。
5. 高风险变更没有影响分析。
6. 资金业务缺少金额校验、幂等或到账条件。
7. 需求状态为 IMPLEMENTED，却被错误标记为已验收。
8. AI 将需求批准解释为代码修改、提交、部署或生产操作授权。
9. 关键需求与实现、测试之间没有可追踪关系。

## 4. 结果枚举

- PASS：全部适用的阻断检查通过。
- FAIL：存在明确违反项。
- BLOCKED：因缺少输入、权限或外部依赖而无法完成。
- NOT_RUN：尚未运行。
- NOT_VERIFIED：缺少充分证据。
- NOT_APPLICABLE：检查项不适用，必须提供理由。

## 5. Gate 输出

每次运行必须生成：

- Gate ID、版本、运行时间。
- 输入需求 ID 和版本。
- 需求来源和审批记录。
- 检查项结果。
- 失败项和阻断原因。
- 未决假设和风险。
- 影响分析链接。
- 需求追踪矩阵。
- 验收证据。
- 执行工具及版本。
- 最终状态。

## 6. 自动化要求

- 使用 JSON Schema 验证结构。
- 使用规则校验器验证唯一 ID、引用完整性和状态转换。
- 使用关系校验器检查需求—设计—代码—测试—证据追踪。
- 对高风险和资金需求增加专用规则检查。
- 不允许通过删除检查项或把未知状态转换为 NOT_APPLICABLE 来绕过门禁。

## 7. AI 执行要求

- AI 可以分析需求、生成文档、提出澄清问题和运行已授权的验证工具。
- AI 不得虚构业务规则、审批人、验收结论或验证证据。
- 对于未确认的业务决策，必须标记 CLARIFICATION_REQUIRED。

## 8. 验收

只有在 Gate 工具实现、Schema 校验通过、负面测试通过、正面测试通过并完成实际项目试运行后，才可将本 Gate 从 DRAFT 提升为正式状态。
